# POPIA data handling model

This document explains how Local Call Recorder handles call data. It is a
technical design note, not legal advice.

## Data flow

Local Call Recorder uses this data flow:

1. You start recording from the Chrome extension popup.
2. Chrome provides a local tab media stream for the active Meet or Teams tab.
3. Optional: Chrome provides a local microphone stream after a browser permission
   prompt.
4. The offscreen extension document records media with `MediaRecorder`.
5. The content script reads visible captions from the meeting page.
6. The extension writes recording and transcript files with `chrome.downloads`.

There is no server step.

## Storage

The extension doesn't create cloud storage or remote accounts. Chrome writes
exports to the device's Downloads folder. The default subfolder is
`Local Call Recorder/`.

## Network behavior

The extension has no general network permission. The only host permissions are
for Google Meet and Microsoft Teams pages so the content script can read visible
captions on those pages.

The source intentionally avoids:

- remote transcription endpoints;
- analytics and telemetry SDKs;
- webhooks;
- upload APIs;
- account login;
- background sync; and
- external model calls.

## POPIA controls supported by the extension

The extension supports privacy-by-design controls:

- explicit recording start by the user;
- consent and notice checklist before recording;
- visible recording banner in the meeting tab;
- local-only media processing;
- local-only transcript export;
- no cloud backend; and
- static tests for common exfiltration primitives.

## Responsibilities outside the extension

The person using the extension remains responsible for legal and operational
controls that software cannot prove alone:

- lawful basis or consent;
- participant notification;
- data subject rights;
- retention period;
- secure device storage;
- encrypted backups if backups exist;
- access control for exported files; and
- deletion or redaction before sharing.

## Export boundary

Data exits the extension only as files generated on the local device. Typical
outputs are:

- `.webm` recording files generated by Chrome;
- `.mp4` files generated locally from `.webm` with `ffmpeg`;
- `.md` transcript files; and
- `.pdf` transcript files generated locally with `pandoc`.

After export, the files are outside extension control. Treat them as personal
information when they identify participants.
